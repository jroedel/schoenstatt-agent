# Spanish review — the 40 rows written on 2026-08-11

Spanish reached **0 untranslated** on production at 12:47 UTC, out of 1,515 live rows, and then
moved again — seven more rows arrived at 12:49 and were translated too (§5), and two retirements
un-retired themselves. See [`close-2026-08-11.md`](close-2026-08-11.md).

This is the 13 of that day's 40 Spanish writes where a native Spanish speaker settles something.

Spanish carries a responsibility the other languages do not, and
[`data/style/es.md`](../data/style/es.md) states it: **Spanish is the pivot language.** It is
the row a translator reaches for when the English key is ambiguous, every error found in the
site's Portuguese came from copying Spanish, and at least one Spanish error was copied into
German. So a Spanish row that is merely *odd* is worth flagging, because oddness travels.

**Every phrase id is a production id.** Resolve by source string, never by carrying an id
between environments.

Corrections are recoverable since the 2026-08-11 deploy — `GET /api/v3/phrases/{id}/history`
returns the exact previous text.

## 1. The category that needs the most careful answer

Four rows in this pass have a **Spanish source string and an empty Spanish row**. That is a
real situation, not a contradiction: the key is what a moderator typed into the record, and
nobody had ever filled the `es` translation of it. Filling it means deciding what a Spanish
row for a Spanish key should contain — and this pass chose *the key with its errors repaired*,
in all four cases.

That is a judgement, and it is the single most important thing in this document. The
alternative was copying the key verbatim, which is defensible and is what
"do not improve what is merely not your preference" would suggest. The argument for repairing:
the key is uneditable, it is what the site falls back to when the row is empty, and writing the
row is the **only** way the site ever shows corrected Spanish. The argument against: it makes
the Spanish row silently differ from what the moderator wrote, and nobody reviewing the record
would see why.

If a reviewer prefers verbatim, all four revert to their keys and this repository gains a rule.

### 1.1 The Mendoza directions

*phrase id 7062 · `Schoenstatt` · route `associations/association/edit` · source: Spanish*

**Key:** `… Una vez que pasó el shopping Palmares a 200m debe ingresar al Loteo Portal de
Benegas, anunaciar al guardia que se dirige al santuario, por el portón ubicado al Nº 3300 de
la Av San Martín Sur, …`

**Written:** `… Una vez que pasó el shopping Palmares, a 200 m debe ingresar al Loteo Portal de
Benegas, anunciar al guardia que se dirige al santuario, por el portón ubicado en el Nº 3300 de
la Av. San Martín Sur, …`

Four repairs: `anunaciar` → `anunciar`, `ubicado al Nº` → `ubicado en el Nº`, `Av` → `Av.`, and
commas around the distance. Note this row keeps `usted` (`debe ingresar`) rather than converting
to the house *tú*, because it is a shrine's own notice and converting the register would be a
larger change than repairing a typo.

### 1.2 How to get to the Monterrey shrine

*phrase id 7090 · `Schoenstatt` · route `associations/association/edit` · source: Spanish*

**Key:** `**Cómo llegar**\n\nEntras por Mederos camino al panteón Guadalupe al lado esta la
entrada a la colonia cañada pides permiso al guardia y hay señalamientos que te llevan al

## 3. Interface strings

### 3.1 `String expected` → `Se esperaba una cadena`

*phrase id 13574 · `default` · route `association`*

A Laminas validator template. `cadena` translates the technical term, following Laminas' own
Spanish conventions and `data/style/es.md`'s rule that Spanish translates this vocabulary where
Italian keeps loanwords. **Portuguese kept the English `string`**, so the four languages now
split. One decision settles all of them.

The rest of this validator family follows phrase 7212, already in all four languages: `El valor
ingresado no parece ser un nombre de red local válido`. That is why 12919 reads `El valor
ingresado no parece ser una dirección IP válida` rather than something invented.

### 3.2 `%sREST API%s` → `%sAPI REST%s`

*phrase ids 13453, 13454 · `Schoenstatt` and `default` · route `shrines.locale`*

The two `%s` are the opening and closing `<a>`, so what sits between them is the **link text**
and its word order changes with the language. Spanish puts the noun first, matching Portuguese.

**The English key has two errors** — `any apps or websites who which to receive`, where `which`
is *wish* and `who` should be *that*. The Spanish translates the intended meaning. The key
cannot be edited from here; the fix belongs where the phrase is generated.

### 3.3 `¿…?` — the opening marks, in three new rows

*phrase ids 7062, 17221 (as a statement), and the checked absence elsewhere*

`data/style/es.md` records that the site's existing Spanish "mostly does this and occasionally
forgets". 7062 opens with `¿Cómo llegar al Santuario de Mendoza?` and keeps its `¿`, following
the key. No new row in this pass omits one — stated so a reviewer can stop looking.

### 3.4 `Replaced` → `Reemplazado el`

*phrase id 17228 · `JTranslate` · route `jtranslate/phrase/edit`*

Heads a column of timestamps, confirmed by reading the template, so *reemplazado el* rather than
a bare participle — matching it `Sostituito il`, de `Ersetzt am`, pt `Substituído em`. The
English is bare. Change one and all four change.

## 4. A four-language inconsistency this pass created

### 4.1 The Ohio shrine — Spanish and Italian translate more than German and Portuguese did

*phrase id 6971 · `Schoenstatt` · route `associations/do-work`*

The English key has three parts: the shrine is being planned, a request for prayer, and then the
practical detail — rosary walks, the street address, the car-park entrance, the 501(c)(3)
status.

**The existing Portuguese and German rows translate only the first two parts** and stop. They
were written before this pass. Spanish and Italian now translate the whole thing, so the four
languages disagree in length: a Spanish reader gets the address and a German reader does not.

Two ways to resolve it and this repository should not pick: extend pt and de, or accept that the
practical detail is US-specific and trim es and it back. Recorded rather than decided.

### 5.2 `How precisely the foundation date is known` → `Con qué precisión se conoce la fecha de fundación`

*phrase ids 17247, 17248, 17249, 17250 · `Schoenstatt` · route `associations/create`*

Options: `Día exacto` / `Solo mes y año` / `Solo año`.

Note the label takes no `¿…?` because it is a select label, not a question — `data/style/es.md`'s
opening-mark rule applies to questions and this is a description of what the field holds. If the
form renders it as a question, it needs `¿Con qué precisión…?` and its closing mark.

The three options were kept parallel, which is why `Solo año` rather than `Solo el año`.
**Four sibling labels on the person form are still untranslated** and will follow this pattern, so
this is a decision about five fields.
