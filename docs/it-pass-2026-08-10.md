A record of one working session, so the writes can be checked and the method reused. The
pass was developed against **the capsule** and then applied to **production**.

On the capsule, `1,349 + 396 = 1,745` — the whole Italian backlog, nothing unaccounted
for. On production, `1,383 + 394 + 18 = 1,795`, likewise complete.

## The one thing that nearly went wrong

**Phrase ids are per-environment, and the two environments agree just often enough to
lull you.** 1,710 of the shared ids matched; **68 did not**, and six of those were live
production ids holding a *different phrase*. Had the capsule's id map been reused, the
Italian for `Is draft?` would have landed on production's `API Tokens`, and five more like
it — applied successfully, reported as success, and unrecoverable.

`tools/apply_translations.py` now builds the id map from the target site on every run, by
matching the source string, and has no way to accept an id map from anywhere else. Two
guards came with it: only rows whose Italian is empty are written, and a source string
matching nothing is reported rather than guessed at. Both are verified — production's 18
pre-existing translations were re-read afterwards and all 18 were unchanged.

A second, subtler version of the same problem: skip decisions are made per
*(text_domain, source string)*, and matching on the string alone would have resurrected
them. `Update on advances` is dead welcome-page copy in the `Application` domain and live
text in `SionModel`. The exclusion list is keyed on the pair for that reason.

**One row off from the classifier, and it is worth saying why.**
`tools/classify.py` puts 1,348 phrases in write buckets and 397 in skip buckets. 1,349
were written, so one skip-bucket phrase has an Italian translation: **6979 is not it —
that one is a genuine write.** The extra is **6976**, `Not official, it was a creation
through the general presidium…`, a moderator's note on one association. It was written
before the record-content rule was tightened to catch prose that short. It is a harmless
write of a correct translation to a row that should probably be retired instead, and it
is left in place rather than re-written, because a translation cannot be un-written.

## How the work was ordered

The instruction was to go screen by screen through the Italian site and see what still
rendered in English, because that yields context a database row does not. That turned out
to be right, and also not sufficient on its own — both halves are worth recording.

**What the screens gave.** [`tools/screens.py`](../tools/screens.py) opens each of the
109 verified Italian pages, finds every backlog phrase in the markup, and records the
**enclosing element** and nearest heading. The element is the part that matters: `Search`
in a `<button>` wants the imperative `Cerca`, the same word as a column header would want
a noun; `Admin notes` in a `<div>` beside `Association Info` is clearly a form label and
not a sentence. Several dozen short labels were decided by their tag and nothing else.

It also corrected the index: a shrine detail page listed at `n = 12` actually renders
**48–60** untranslated strings, because the index credits each shared template string to
whichever route triggered it first. The template strings — `Country`, `Website`, `Phone`,
`Foundation date`, `Parent organization` — are the highest-value work in the corpus, each
one landing on 77 to 109 pages at once.

**Where the screens ran out.** Only **399 of 1,745** phrases are visible on any public
page. The rest are behind a sign-in, on moderator edit forms, or on no page at all. For
those, the context came from the other four languages, which the API returns with every
phrase, plus the route name.

## The three things that decided most translations

1. **The sibling languages settle house convention, not Italian.** Whether a term is
   translated at all, and what shape it takes, is visible in what es/pt/de did. What the
   Italian word *is* they cannot say — and where they disagree with each other, that
   disagreement is the signal that a decision is needed. Those became review-queue
   entries.
2. **The movement's own Italian sources settle charism vocabulary.** This is what closed
   the biggest open question in the glossary. `Schoenstatt wayside shrine` had three
   mutually incompatible sibling renderings (es *hermitage*, pt *hermitage*, de *wayside
   pillar*); the movement's Italian page on the network of shrines has a section headed
   **`Le edicole di Schoenstatt`**, glossing it `Le cappelle lungo la strada (edicole)`.
   The same source settled `Santuario Originale`, `Alleanza d'Amore`, `Capitale di
   Grazie`, `Madonna Pellegrina`, and the eighteen branch names.
3. **A large part of the backlog is not translatable work.** 397 phrases, in eleven
   documented buckets. Finding this out first is what made the rest tractable.

## What was found along the way

Three things worth acting on that are not translation work. All are written up in
[`phrase-table-noise.md`](phrase-table-noise.md).

- **A JWT is sitting in the phrase table, twice over.** The api-tokens screen appends the
  freshly minted token to its success message before translating, so the token became a
  phrase key *and* an English translation. Four rows, all from 2026-08-10. They are
  capsule tokens, so nothing live is exposed — but the same code path on production writes
  a production token into a table any `sch_api_translator` account can read, and into the
  compiled catalogs on disk. Section 4, including the handling.
- **`Books` is not books.** This file's own guidance said the domain was risky because it
  held book titles needing published Italian editions found. It holds library interface
  strings and text-corpus artefacts, and almost no titles. CLAUDE.md is corrected.
- **Some English on the Italian page cannot be translated.** The breadcrumb partial
  renders labels without `translate()`, so a shrine page shows `Shrines` in the breadcrumb
  and `Santuari` in the navigation. Section 8.

## Checking the writes

The reviewable unit is the source string, not the phrase id, because one string can span
up to seven text domains — `Schoenstatt Link` exists as seven separate rows. The batches
are `tr_*.json` files pairing source string to Italian, applied by
[`tools/apply_translations.py`](../tools/apply_translations.py), which dry-runs by
default. Regenerating the classification and the review queue reproduces the counts
above.

To see a page as it now stands, open any URL from
[`translation-index.md`](translation-index.md); they all still resolve.

## What is next

1. **The review queue.** 100 entries, ranked charism vocabulary first. Two of them are
   the ones a wrong answer would hurt most: `Heiligtum der Verbundenheit` and
   `Heiligtum der Werktagsheiligkeit` are Kentenich terms of art where the Romance
   siblings coined words Italian cannot borrow.
2. **Production.** The v3 endpoints are reachable there and the phrase schema matches the
   capsule exactly, `it` included. The blocker is the credential: the production
   translator token returns `401`, which needs an administrator session to diagnose. See
   CLAUDE.md.
3. **A decision on the Kentenich corpus.** 219 phrases on the `text` route, all with
   German source strings, translated by no language. Whether that corpus should be
   translated at all is a question for the movement.
4. **German and Portuguese.** Untouched by this pass, and both trail Spanish. The same
   tooling works for them: `classify.py` and `screens.py` take a language code, and the
   glossary's structure is per-language.
