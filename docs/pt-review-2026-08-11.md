## 1. The translation-history screen — all six new rows

These six make up the screen a translator sees when a phrase's translations have been replaced
before. They are the interface for the recoverability feature itself, so a translator reads them
at the moment they are trying to undo something.

All six were written in it/de/es/pt together, and two of them are **structural choices made
identically in all four languages** — changing the Portuguese means changing the other three.

### 1.1 `Previous versions` → `Versões anteriores`

*phrase id 17223 · `JTranslate` · route `jtranslate/phrase/edit` · an `<h2>`*

### 1.2 `Previous text` → `Texto anterior`

*phrase id 17226 · a `<th>`, beside `Language`, `Note` and `Replaced`*

### 1.3 `Note` → `Nota`

*phrase id 17227 · a `<th>`*

The column holds the translator's stated **reason** for replacing a translation — the `_note`
sent with the write — not a general annotation. `Nota` is the plain choice; if Brazilian
Portuguese wants `Justificativa` or `Motivo` here, this is the row.

### 1.4 `Replaced` → `Substituído em` — a structural choice

*phrase id 17228 · a `<th>`*

`Replaced` heads a column of **timestamps**. That was confirmed by reading
`module/JTranslate/view/j-translate/j-translate/edit.phtml`, not inferred — it sits beside
`Language`, `Previous text` and `Note` in the same `<thead>`.

So all four languages render it as *replaced on* rather than as a bare participle: pt
`Substituído em`, it `Sostituito il`, de `Ersetzt am`, es `Reemplazado el`. The English is bare.
If that column ever shows something other than a date, all four are wrong together.

### 1.5 `%s previous version(s) — a translation here has been replaced before` — a structural choice

*phrase id 17221 · `JTranslate` · route `jtranslate` · a tooltip on a clock icon*

**Written:** `Versões anteriores: %s — uma tradução aqui já foi substituída`

The English hedges the plural with `version(s)`. `%s` is a count and is **always at least 1**,
because the icon only renders when the count is positive — so a literal rendering would produce
`1 versões anteriores`. Moving the count behind a colon avoids the agreement problem without
importing the `(s)` hedge, and all four languages do the same. It is a tooltip, so width is not
a constraint.

### 1.6 The help block under the heading

*phrase id 17224 · `JTranslate` · route `jtranslate/phrase/edit`*

**Written:** `O texto que as escritas nesta frase substituíram, do mais recente ao mais antigo.
Nada do que segue é mais exibido pelo site: é guardado para que uma alteração possa ser
revertida e para que o motivo de uma alteração sobreviva a quem a fez.`

`as escritas nesta frase` is carrying what the awkward English `What writing to this phrase has
replaced` does, and neither is graceful. This is the row most likely to want rewriting rather
than correcting — if there is a natural Brazilian phrasing for "the text that previous writes
replaced", it belongs here.

Note `do mais recente ao mais antigo` where the English says only `newest first`. The expansion
is deliberate: `mais recente primeiro` reads as an instruction rather than a description.

## 2. A defect in an existing Portuguese row — not written this pass

This is the useful half of the document.

### 2.1 Spanish weekdays left in the Portuguese row

*phrase id 6980 · `Schoenstatt` · route `associations/association` · source: Spanish*

**Current Portuguese:**

```
**Horário de abertura**:

 7:00 hrs - 22:00 hrs

**Missas**:

Domingo: 10:00 hrs, 19:00 hrs

**Missa de Aliança**:

 20:00 hrs. Todos os dias 18 de cada mês

**Santo Rosario**:

Jueves: 19:00 hrs

Sábado: 0:00 hrs
```

Three things are wrong, and they are the exact failure mode `data/style/pt.md` names as the one
that produced **every** error found in the site's existing Portuguese: copying the Spanish and
only partly converting it.

- **`Jueves` is Spanish.** Portuguese is `Quinta-feira`.
- **`Sábado` is spelled the same in both languages**, so it is not evidence by itself — but it
  sits directly under `Jueves`, in the same block, which is.
- **`Santo Rosario` is Spanish.** Portuguese is `Santo Rosário`, with the accent.

By the standard the maintainer set on 2026-08-11 this is correctable without asking: a word from
another language sitting in the row is on the list of things that are demonstrably wrong rather
than merely not one's preference. **It was not corrected**, for one reason and it is not
timidity: the same row's `Sábado: 0:00 hrs` says the Holy Rosary is at midnight on Saturday,
which is very likely a data-entry error on the association record itself. Correcting the
Portuguese around a wrong hour would make the row look reviewed while leaving a wrong Mass time
in front of a pilgrim in five languages.

So the two want fixing together, and the hour has to come from somebody who can see the record.
The Italian written in this pass renders the hour faithfully for the same reason — see
[`it-review-2026-08-11.md`](it-review-2026-08-11.md) §6.1.

When the hour is settled, the Portuguese correction is one call to
`tools/apply_corrections.py`, which asserts the current value before replacing it.

## 3. One four-language inconsistency, recorded not resolved

### 3.1 The Ohio shrine — Portuguese translates less than Spanish and Italian now do

*phrase id 6971 · `Schoenstatt` · route `associations/do-work`*

The English key has three parts: the shrine is in planning, a request for prayer, and the
practical detail — rosary walks, the street address, the car-park entrance, the 501(c)(3) status.

**The existing Portuguese row stops after the second part**, as does the German. Both predate
this pass. Spanish and Italian were written this pass and translate the whole key, so a Spanish
reader now gets the Ohio address and a Portuguese reader does not.

Either extend pt and de, or accept the practical detail as US-specific and trim es and it. Not a
decision this repository should make alone, and not a defect in any one row.

### 3.2 `String expected` — Portuguese is the odd one out, and may be right

*phrase id 13574 · `default` · route `association`*

The existing Portuguese, written earlier the same day, is `Tipo inválido. Esperava-se uma
string` — keeping the English `string`. The three rows written this pass translate it: it `una
stringa`, es `una cadena`, de `Zeichenkette`.

`data/style/pt.md` lists what stays in English and `string` is not on it, but the list is
explicitly not exhaustive and Brazilian developer usage does keep it. **Portuguese may be the
correct one and the other three the drift.** One decision settles four rows; recorded here as
well as in the other three documents so whoever answers sees it from every side.
